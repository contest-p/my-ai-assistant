# 기술스택.md — 전역 후 1년, 내 소비를 아는 AI 비서

## 최종 확정 스택

- **백엔드**: Python 3.11 · FastAPI · uvicorn · firebase-admin · openai · python-dotenv
- **DB**: Firebase Firestore
- **프론트**: HTML / CSS / Vanilla JavaScript (`fetch` API), 빌드 도구 없음
- **AI**: OpenAI 호환 API — 코디세이 프록시 엔드포인트(`OPENAI_BASE_URL`) 경유, 모델 `gpt-5.5`
- **배포**: Render (Web Service) / Vercel (Static, Other preset)
- **저장소**: GitHub 단일 Repository
- **구조**: `backend/` + `frontend/` 디렉터리로 분리

## 미션이 이미 고정한 부분 (선택의 여지 없음)

FastAPI, Firestore, OpenAI API, Render 배포, Vercel 배포, 바닐라 HTML/CSS/JS(프레임워크 금지)는
미션 6·7번(개발환경/제약사항)에서 명시적으로 요구하는 항목이라 그대로 따른다.

## 단일 레포 + 디렉터리 분리를 선택했을 때 반드시 챙길 것

레포를 하나로 합쳤기 때문에, Render/Vercel 둘 다 **레포 최상위가 아니라 서브폴더를 보게**
설정을 명시적으로 지정해야 한다. 안 하면 최상위에서 실행 파일/정적 파일을 찾다가 배포가 실패한다.

| 플랫폼 | 설정 | 값 |
|---|---|---|
| Render | Root Directory | `backend` |
| Render | Start Command | `uvicorn main:app --host 0.0.0.0 --port $PORT` |
| Vercel | Root Directory | `frontend` |
| Vercel | Framework Preset | `Other` (빌드 커맨드 없음, 정적 사이트) |

8단계(배포하기) Task에 이 4개 항목을 체크리스트로 넣어둘 것.

## AI 모델 — `gpt-5.5`로 확정 (Phase 6 완료)

모델명은 코드에 하드코딩하지 않고 환경변수(`OPENAI_MODEL`)로 분리해서, 나중에 모델을
바꿀 때 코드 수정 없이 값만 바꾸면 되게 설계했다.

**OpenAI 직접 호출이 아니라 코디세이 프록시 경유.** 실제 발급받은 키가
`sk-cody-live-`로 시작하는 코디세이 전용 키였고, `https://copa.codyssey.kr/v1`라는
override URL(`OPENAI_BASE_URL`)을 OpenAI 클라이언트의 `base_url`로 넘겨야 동작함을
Phase 1에서 확인했다(PRD 27번 참고).

**모델 선정 (Phase 6, 2026-09)**: `/models` 엔드포인트로 프록시가 실제 지원하는
모델 11종을 확인했다 — GPT뿐 아니라 Claude(haiku-4, opus-4-7/4-8, sonnet-4), Gemini
(3-flash, 3.1-flash-lite, 3.1-pro) 계열까지 포함. 이전에 적어뒀던 "일반 OpenAI API
기준 GPT-5.6 Luna" 리서치는 이 프록시 목록에 GPT-5.6 자체가 없어서 애초에 적용 대상이
아니었음이 확인됨 — 아래에 취소선으로 남겨둔다.

최종적으로 `gpt-5.5`를 채택했다. `gpt-5-mini`/`gpt-5.4-mini`처럼 더 저렴할 가능성이
있는 하위 모델도 목록에 있었지만, 이미 `gpt-5.5`로 6.7 통합 테스트까지 완료된 상태이고
개인 프로젝트라 트래픽이 적어 재검증 없이 유지하기로 결정했다(사용자 확인).

## 세부 결정 사항과 이유

| 항목 | 결정 | 이유 |
|---|---|---|
| Python 버전 | 3.11 | Render 지원 확실, FastAPI/Pydantic v2와 궁합 좋음 |
| 프론트엔드 HTTP 통신 | 순수 `fetch()` | 프레임워크 금지 요구사항에 맞춰 axios 등 라이브러리도 배제 |
| Render 실행 방식 | uvicorn 직접 실행 | 이 규모에 gunicorn까지 얹는 건 과함 |
| Vercel 배포 방식 | Framework Preset `Other`, 빌드 커맨드 없음 | 바닐라 HTML은 빌드 자체가 불필요. Next.js로 오인해 자동 빌드를 시도하는 걸 방지 |
| 자동 테스트(pytest 등) | 생략 | 미션 요구사항은 "최소한의 예외 처리"뿐 — 테스트 프레임워크는 범위 밖 |
| requirements.txt 버전 고정 | 개발 단계에서 `pip freeze`로 고정 | 실제 설치 결과를 고정하는 게 지금 버전 번호를 추측하는 것보다 안전 |
